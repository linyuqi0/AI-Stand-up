# 健康提醒应用（Stretch & Sip）产品规划

## 一、产品概述

### 1.1 产品定位
一款面向久坐办公人群的健康提醒工具，通过可爱简约的界面设计，帮助用户在工作中养成定时站立、喝水、护眼等健康习惯，预防职业病，提升工作幸福感。

### 1.2 目标用户
- **核心用户**：25-40岁办公室白领、程序员、设计师等久坐人群
- **次要用户**：学生、自由职业者、居家办公人群
- **用户痛点**：久坐忘记起身、喝水量不足、用眼过度、工作与健康失衡

### 1.3 产品Slogan
> "工作再忙，也要好好照顾自己 ♡"

## 二、核心功能模块

### 2.1 提醒中心（Reminder Hub）

#### 2.1.1 内置提醒类型
| 提醒类型 | 默认频率 | 持续时长 | 说明 |
|---------|---------|---------|------|
| 💧 喝水提醒 | 每45分钟 | - | 每日目标8杯（2000ml），可自定义杯量 |
| 🧍 站立提醒 | 每60分钟 | 3分钟 | 起身活动、伸展肢体 |
| 👀 护眼提醒 | 每90分钟 | 20秒 | 20-20-20法则：看20英尺外20秒 |
| 🧘 拉伸提醒 | 每120分钟 | 5分钟 | 简单颈部/肩部/腰部拉伸动作 |
| 😊 心情打卡 | 每日 18:00 | - | 记录今日心情与健康感受 |

#### 2.1.2 提醒自定义能力
- **时间设置**：开始时间、结束时间、提醒间隔、提醒次数
- **工作日设置**：自定义工作日（周一至周日任选）
- **提醒方式**：
  - 应用内弹窗提醒（带可爱动画角色）
  - 通知栏推送
  - 震动反馈
  - 声音提醒（多种可爱音效可选）
  - 桌面小组件实时状态
- **跳过/延迟**：支持"跳过本次"、"5分钟后再提醒"、"15分钟后再提醒"

#### 2.1.3 智能提醒逻辑
- **专注模式**：检测到用户正在使用全屏应用时自动延后提醒
- **午休时段**：自动识别午休时间（12:00-14:00）暂停提醒
- **会议检测**：（可选）日历权限读取，会议期间静音提醒
- **假日模式**：法定节假日自动暂停工作日提醒

## 三、技术架构选型

### 3.1 跨平台技术方案对比

| 方案 | 优势 | 劣势 | 推荐度 |
|-----|-----|-----|-------|
| **Flutter** | 一套代码多端运行、UI一致性高、性能接近原生、Dart语言高效 | 生态相对年轻、包体积稍大 | ⭐⭐⭐⭐⭐ |
| React Native | JS生态丰富、社区活跃 | 性能瓶颈、UI一致性需额外处理 | ⭐⭐⭐⭐ |
| 原生开发（Swift + Kotlin） | 性能最佳、原生体验好 | 开发成本高、维护两套代码 | ⭐⭐⭐ |
| Uni-app | 国内生态好、小程序支持 | 性能一般、复杂UI吃力 | ⭐⭐ |

**推荐方案：Flutter**
- 理由：UI一致性高（保证简约可爱风格统一）、性能优秀、开发效率高、支持桌面端扩展

### 3.2 技术栈规划

#### 3.2.1 移动端（iOS / Android）
- **框架**：Flutter 3.x + Dart 3.x
- **状态管理**：Riverpod / Bloc
- **本地存储**：Isar / Hive
- **通知推送**：
  - iOS：UserNotifications + Push Notifications
  - Android：AlarmManager + WorkManager + FCM
- **数据图表**：fl_chart

#### 3.2.2 iOS 小组件
- **技术**：SwiftUI + WidgetKit
- **数据共享**：App Group + UserDefaults / Shared Core Data
- **与Flutter通信**：Method Channel + App Group 共享数据

#### 3.2.3 Android 小组件
- **技术**：App Widgets + Jetpack Glance
- **数据共享**：SharedPreferences（MODE_PRIVATE 多进程访问）

#### 3.2.4 桌面端（macOS / Windows）
- **macOS**：SwiftUI + WidgetKit（通知中心）+ MenuBar Extra
- **Windows**：WinUI 3 / Windows App SDK
- **备选方案**：Flutter Desktop 构建完整桌面应用

#### 3.2.5 后端服务（可选，按需启动）
- **方案A（轻量）**：Firebase / Supabase（BaaS，快速上线）
- **方案B（自建）**：
  - 后端框架：Go / Node.js
  - 数据库：PostgreSQL
  - 缓存：Redis
  - 部署：Docker + Kubernetes

## 四、UI/UX 设计规范

### 4.1 设计风格：简约可爱（Soft Minimalism）

#### 4.1.1 视觉关键词
- 柔和圆润：大圆角、柔和阴影
- 轻盈通透：渐变色、毛玻璃效果
- 可爱治愈：Q版角色、柔和配色
- 简洁有序：留白充足、层次清晰

#### 4.1.2 色彩系统
- **主色调**：樱花粉 `#FFB6C1` → 柔和粉 `#FFC8DD`
- **辅助色**：
  - 薄荷绿 `#B5EAD7`（站立/运动）
  - 天空蓝 `#A8DADC`（喝水）
  - 暖阳黄 `#FFE5B4`（心情/能量）
  - 薰衣草紫 `#E0BBE4`（护眼/放松）
- **中性色**：
  - 背景：`#FFFAFB`（暖白）
  - 文字主：`#2D3436`
  - 文字次：`#636E72`
  - 分割线：`#DFE6E9`

#### 4.1.3 字体系统
- **中文**：思源黑体 / 苹方
- **数字/英文**：Poppins / Nunito（圆润可爱）
- **字号层级**：
  - 大标题：28px / Bold
  - 标题：20px / SemiBold
  - 正文：16px / Regular
  - 辅助文字：14px / Regular
  - 小字：12px / Regular

#### 4.1.4 圆角与间距
- **卡片圆角**：20px
- **按钮圆角**：16px
- **组件圆角**：12px
- **基础间距单位**：4px / 8px / 12px / 16px / 24px / 32px

#### 4.1.5 动效规范
- **过渡时长**：200ms（快速）/ 300ms（标准）/ 500ms（柔和）
- **缓动曲线**：Cubic Bezier (0.4, 0.0, 0.2, 1)
- **动画类型**：
  - 弹性弹出（Bounce）
  - 淡入淡出（Fade）
  - 滑动进入（Slide）
  - 缩放变换（Scale）

### 4.2 核心页面设计

## 八、风险与应对

### 8.1 技术风险

| 风险 | 影响 | 应对措施 |
|-----|-----|---------|
| Flutter 与原生小组件通信复杂 | 中 | 采用 App Group 共享数据，设计统一数据模型 |
| Android 后台限制导致提醒不准 | 高 | 多策略兜底（AlarmManager + WorkManager + 厂商通道），引导用户加白名单 |
| iOS 通知权限被拒 | 中 | 优雅的权限引导弹窗，解释清楚用途 |
| 桌面端开发量超预期 | 中 | 优先做菜单栏/托盘轻量版，完整桌面延后 |

### 8.2 产品风险

| 风险 | 影响 | 应对措施 |
|-----|-----|---------|
| 用户新鲜感过后流失 | 高 | 成就系统、角色养成、社交互动提升粘性 |
| 提醒过多造成打扰 | 中 | 智能免打扰、可调节频率、专注模式 |
| 同品类竞争激烈 | 高 | 差异化：可爱治愈风格、多端同步、小组件体验 |

### 8.3 上架风险

| 风险 | 影响 | 应对措施 |
|-----|-----|---------|
| 国内上架需要软著 | 高 | 提前申请软件著作权（通常1-2个月） |
